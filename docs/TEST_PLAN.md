## 一、测试目标

1. **验证功能正确性**：确认 README 声明的 12 项能力在真实环境中确实生效，而非仅"编译通过"。
2. **建立性能基线**：取得可复现的 fps / CPU / 内存数据，作为后续重构与优化的对比基准（历史教训：P0.3 因缺基线导致 60→32fps 回退未及时发现）。
3. **暴露边界与异常缺陷**：重点验证"现场改错配置""素材缺失""非法控制包"等展会现场真实会发生的场景。
4. **验证长时间稳定性**：24/7 无人值守是核心使用场景，必须验证热机稳态与资源不泄漏。
5. **输出可交付结论**：形成缺陷清单与通过/不通过判定，支撑是否进入现场验收（GA）的决策。

## 四、测试策略与方法

### 4.1 总体策略

**分层推进，前一层不通过不进入下一层**：

```
第一层  冒烟（Smoke）     → 确认可测，5 分钟内出结论
第二层  功能（Functional）→ 逐条验证 F-01~F-20
第三层  边界（Boundary）  → 参数上下限与越界
第四层  异常（Exception） → 故障注入，验证"不翻车"
第五层  性能（Performance）→ 冷机短跑 + 热机长跑
第六层  稳定（Stability） → 长时间无人值守
第七层  回归（Regression）→ 缺陷修复后重验
```

**关键原则**（来自本项目历史教训）：

- **先基线，后优化/重构**：任何性能结论必须有前后对照数据，且**同机同温**（本项目实测冷热差 2~3 倍）。
- **用有细节的素材验证颜色/几何**：纯色素材看不出 UV 错位一类的 bug（README 踩坑第 15 条）。
- **对抗式验证**：不看"应该对"，看实测数据；日志里的数字才算数。

### 4.2 测试类型与对应方法

| 类型 | 方法 | 覆盖模块 | 判定方式 |
|---|---|---|---|
| 冒烟测试 | 固定 8 条用例，每次构建后必跑 | M1/M2/M3/M4 | 全通过才继续 |
| 功能测试 | 按 F-01~F-20 逐条正向验证 | 全部 | 实测现象 + 日志关键字 |
| 边界测试 | 参数取上下限与越界值 | M1/M3/M6 | 与代码校验分支一致 |
| 异常测试 | 故障注入（删文件、改错配置、发非法包、拔显示器） | M1/M6/M7/M9 | 不崩溃、不黑屏、有明确日志 |
| 性能测试 | `--bench N --json`，冷机短跑 + 热机长跑 | M9 | fps / CPU / 内存数值 |
| 稳定性测试 | 连续运行 ≥2 小时（现场按计划时长） | M9 | 无崩溃、无泄漏、无音画漂移 |
| 兼容性测试 | 不同 Windows 版本 / 显卡 / 显示器数量 | M8/M10 | 能启动且核心功能正常 |
| 回归测试 | 缺陷修复后重跑受影响模块 + 冒烟 | 按改动范围 | 原缺陷不再现且无新缺陷 |

# 2. 跑单测

### 7.4 异常测试（故障注入）

| ID | 注入方式 | 预期结果 | 判定标准 |
|---|---|---|---|
| ET-01 | 播放中删除某层的 `clips\*.mov` | 该层报错，其他层与切场不受影响 | 不崩溃、不整体黑屏 |
| ET-02 | 把某层路径改为不存在文件 | 启动日志 `[错误] 打不开`，该层被跳过 | 其余层正常播放 |
| ET-03 | 放入 0 字节 `empty.mov` | 打开失败，跳过该层 | 不崩溃 |
| ET-04 | 放入截断的 `truncated.mov` | 打开或解码失败，跳过/报错 | 不崩溃，有日志 |
| ET-05 | 放入伪视频 `fake.mov` | 打开失败，跳过 | 不崩溃 |
| ET-06 | **播放中**改错 `layers.txt` 保存 | `[热重载] 新配置无可用队列，忽略本次变更，继续播旧配置` | **不黑屏**（现场改错字的关键防线） |
| ET-07 | 配置文件被删除 | `[错误] 打不开配置文件` | 继续播当前内容，不崩溃 |
| ET-08 | 拔掉第二台显示器 | 不崩溃；重启后按新拓扑排列 | 有日志 |
| ET-09 | 断网启动 | 不受影响（依赖全本地） | 正常播放 |
| ET-10 | UDP 发空包 | 无回执 | 不崩溃、不影响播放 |
| ET-11 | UDP 发随机乱码 | 无操作 | 不崩溃 |
| ET-12 | UDP 发 >512 字节超长包 | 被截断处理 | 不崩溃（缓冲区为 512 字节） |
| ET-13 | OSC 发畸形包（首字节 `/` 但无 `\0` 结尾） | 解析失败，无操作 | 不崩溃 |
| ET-14 | OSC 发 `#bundle` 但内容为空 | 无操作 | 不崩溃 |
| ET-15 | 未开播放器时发 UDP | 无回执（脚本应提示超时） | 脚本不卡死 |
| ET-16 | 制造持续低帧（临时用极大负载，或按验收清单用 `--max-fps` 压低） | `fps<5` 持续 5 秒 → **主动退出** | 进程自行退出，等待外部（任务计划/自启）拉起 |
| ET-17 | 播放中强行杀进程后重启 | 能通过自启/任务计划恢复播放 | 恢复后画面声音正常 |
| ET-18 | 磁盘空间不足时预加载 | 预加载失败有日志 | 不崩溃 |

**异常测试总判定标准（一句话）**：
**任何异常注入下，程序都不得崩溃、不得出现不可恢复的黑屏，且必须在日志中留下可定位的错误信息。**

### 7.6 性能测试

| ID | 场景 | 命令 | 判定标准 |
|---|---|---|---|
| PT-01 | 720p 4 层（基准） | `--bench 30 --json --port 0 --size 1280x720` | 平均 fps ≥ 55（开发机基准 59） |
| PT-02 | 4K 10 层 | `bench4k.txt --bench 60 --json` | 记录冷机值，**必须同时记录热机值** |
| PT-03 | 4K 15 层 | `bench15.txt` | 仅摸上限，记录数据 |
| PT-04 | 混合编码 | `bench15mix1080.txt` | HAP + H.264(NVDEC) 共存不冻结 |
| PT-05 | 自适应帧率 | 高负载下观察日志 | 出现 `[自适应] 负载高...maxFps 降至 N`，回升正常；**下限 30** |
| PT-06 | NVDEC 生效 | 看启动日志 | `[NVDEC] h264_cuvid 已启动`；用 `HAPPLAYER_NO_NVDEC=1` 对照测 CPU 占用 |
| PT-07 | 内存占用 | 任务管理器观察 | 注意：预加载会占用较多内存（实测 4 秒 720p QTRLE 约 421MB），属设计行为，需确认总量可接受 |

**性能判定原则（务必遵守）**：

- **冷热必须分开记录**：本机持续满载约 10 秒后降频，冷热差 2~3 倍。`--bench` 短跑只能作功能正确性证明，**不能作性能结论**。
- **对照组必须同机同温**：同一配置隔几小时跑可能差 2~3 倍，全是散热变量。
- **验收数字只在展项主机上取**：跑满计划单次运行时长后取热机稳态值。

### 7.7 稳定性测试

| ID | 时长 | 观察项 | 判定标准 |
|---|---|---|---|
| ST-01 | ≥2 小时（现场取计划时长） | 分段记录 fps | 热机后 fps 达设计目标 |
| ST-02 | 同上 | 内存/显存曲线 | 无持续上涨（允许预加载阶段的阶跃，之后须平稳） |
| ST-03 | 同上 | 音画同步 | 无可感知漂移 |
| ST-04 | 同上 | 冻屏/崩溃 | 零次 |
| ST-05 | 7 天（可选） | 健康监控 | 到 7 天主动退出，等待外部拉起 |
| ST-06 | 播放期间 | 系统休眠 | 系统不睡眠、显示器不关 |

## 八、执行流程

```
1. 环境准备（§5）
   ├─ 装 VC++ 运行时、确认驱动、电源高性能
   ├─ 干净重建 + 单测 + 时间戳对账      ← 不通过则阻断
   └─ 拷贝交付包到测试机

2. 冒烟（SM-01~08）                    ← 任一失败则阻断，回到开发

3. 功能测试（FT-01~18）    → 逐条填打分表 A~F 组
4. 远程控制（§7.5）        → 填 G 组
5. 窗口与多屏（FT-14~16）  → 填 H 组

6. 边界测试（BT-01~25）    → 结果记入「问题记录」页
7. 异常测试（ET-01~18）    → 结果记入「问题记录」页

8. 性能（PT-01~07）        → 冷机短跑先做，热机长跑放最后
9. 稳定（ST-01~06）        → 长跑期间可并行整理已发现缺陷

10. 汇总 → 缺陷分级 → 判定 → 报告
11. 修复 → 回归（§11）→ 复测
```

**执行顺序约束**：边界与异常测试必须在功能测试之后（先确认基本可用，再折腾它）；性能长跑放最后（避免机器发热影响前面的功能判断）。

## 十一、缺陷处理与回归验证流程

### 11.1 缺陷分级

| 级别 | 定义 | 响应 | 示例 |
|---|---|---|---|
| **P0 致命** | 崩溃、无法启动、黑屏、播放中断 | 立即阻断，修复后全套重测 | 启动即崩、切场黑屏不恢复 |
| **P1 严重** | 核心功能不生效，无规避方案 | 本轮必须修复 | 自动切场失效、热重载黑屏、音画不同步 |
| **P2 一般** | 次要功能异常，有规避方案 | 排期修复，可带病上线 | 某条 OSC 命令无效、日志文案错误 |
| **P3 轻微** | 体验/文案/优化建议 | 记录，择期处理 | 提示不友好、配置项未校验 |

### 11.2 处理流程

```
发现 → 登记（问题记录页，含复现步骤+证据）
     → 定级（P0~P3）
     → P0/P1：阻断当前测试，转开发
     → 修复
     → 开发自验：跑冒烟 + 该模块用例
     → 回归验证（§11.3）
     → 关闭（记录修复版本 + 回归结果）
```

**每个缺陷必须可复现**。无法复现的记为"偶发"，保留日志，长跑中重点观察，**不得直接关闭**。

### 11.3 回归验证流程

| 改动范围 | 回归范围 |
|---|---|
| 配置解析 | 冒烟 + BT-01~25 + ET-06/07 |
| 队列调度/切场 | 冒烟 + FT-01~05 + ST-01 |
| 解码 | 冒烟 + FT-01~04 + PT-01~04 |
| 音频 | 冒烟 + FT-08/09 + ST-03 |
| 远程控制 | 冒烟 + §7.5 全表 |
| 渲染/布局 | 冒烟 + FT-06 + FT-14~16 |
| 性能相关 | **必须重跑基线并与改前对比（同机同温）** |

**回归必跑冒烟套件（SM-01~08）**，无论改动多小。

> **强建议**：本项目**当前无版本控制**（不是 git 仓库），无法 `git checkout` 回退，也难以确认改动范围。回归前请先执行 `git init` 建立基线——这既是本项目经验教训第 2 条的要求，也是回归验证能落地的前提。

## 十二、已知缺陷与疑点（测试前必读）

| ID | 描述 | 影响 | 处理 |
|---|---|---|---|
| **D-01** | 队列的**图层行不支持行尾 `#` 注释**，`0\|1\|a.mov  # 背景` 会把注释当作路径一部分，导致 `[错误] 打不开` | 现场改配置易踩 | 测试配置已规避；建议在 FT/BT 中确认，后续应修复解析器 |
| **D-02** | OSC `/queue N` 疑似未生效：回执 `OK queue 1`，但随后 `status` 仍显示原队列（文本命令正常） | 中控用 OSC 跳场可能失效 | 打分表 G4 重点验证；若复现，至少 P2 |
| **D-03** | `monitor` / `fade` / 自定义矩形 `x,y,宽` / 图层音量**无范围校验**，越界值被直接接受 | 配置错误无提示 | BT-12~14、BT-20 已覆盖，确认"不崩溃"即可 |
| **D-04** | 4K 压测素材位于 `C:\hap4k_clips`，未随项目归档 | 换机无法复现性能测试 | 测试前确认素材已拷贝，否则 PT-02~04 免测 |
